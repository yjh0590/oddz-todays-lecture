# 오늘의 강의 - 가톨릭대 LMS v0.2.0

가톨릭대 Canvas/LearningX용 실험 버전입니다.

## 이번 버전의 핵심
- 인천대 버전처럼 `영상 선택` / `오늘 재생할 목록` 2단 UI로 변경
- 현재 과목에서 여러 강의를 선택해 오늘 목록에 추가
- 다른 과목으로 이동해도 오늘 목록 유지
- 여러 과목의 강의를 한 목록에 쌓아 순서대로 실행 가능
- `전체 시작`, `중지` 제공
- 짧은 오프닝 영상은 종료 판정에서 제외
- 실제 UniPlayer 재생 버튼을 자동 클릭
- 종료 시 beforeunload 경고를 자동 이동 시점에만 해제
- 목록으로 돌아온 뒤 React 렌더 안정화 시간을 준 후 다음 강의를 실제 클릭 이벤트 순서로 실행

## 설치
1. ZIP 압축 해제
2. Chrome에서 `chrome://extensions`
3. 개발자 모드 켜기
4. `압축해제된 확장 프로그램을 로드합니다`
5. 압축 해제한 폴더 선택

## 사용
1. 첫 과목의 `강의/출결` 목록 화면으로 이동
2. 확장프로그램을 열고 원하는 강의 체크
3. `선택한 강의를 오늘 목록에 추가`
4. 다른 과목으로 이동해 같은 방식으로 추가 가능
5. `전체 시작`
6. 목록 순서대로 강의를 열고 재생

## 참고
- 아직 가톨릭대 LearningX의 현재 DOM 구조를 기준으로 만든 테스트 버전입니다.
- 출결 API나 진도율 값을 직접 수정하지 않습니다.
- 실제 플레이어의 재생/종료와 LMS 화면 이동만 자동화합니다.

## v0.5.1 핵심 수정
이번 문제의 원인을 이전보다 구체적으로 잡았습니다.

1. 다음 강의를 클릭하기 **전** 현재 CMS `/em/<content-id>` 목록을 스냅샷으로 저장합니다.
2. 강의를 클릭한 뒤에는 그 이전 content-id는 자동재생 대상에서 완전히 제외합니다.
3. 실제로 새로운 `/em/<content-id>`가 나타난 뒤에만 해당 플레이어의 `재생` 버튼을 누릅니다.
4. 약 2초만 재생된 상태를 성공으로 보지 않습니다.
5. 새 강의의 실제 영상 시간이 최소 5초 이상 증가하고 계속 재생 중인 것을 확인해야 자동재생 처리를 종료합니다.
6. 따라서 `약 2초 재생 → 검은 화면 정지`가 발생하면 감시가 계속 살아 있고, 다시 `재생` 버튼을 누릅니다.
7. UI를 접었을 때 오른쪽 가운데 `▶` 버튼으로 다시 펼칠 수 있게 유지했습니다.

## v0.5.9 콘솔 경고 정리
- `beforeunload-hook.js`가 `EventTarget.prototype.addEventListener` 전체를 가로채던 구조를 제거했습니다.
- 기존 구조에서는 LMS/UniPlayer가 `unload` 이벤트를 등록할 때도 우리 wrapper를 통과해, Chrome의 `Permissions policy violation: unload is not allowed` 경고가 `beforeunload-hook.js` 줄 번호로 표시될 수 있었습니다.

- 따라서 `unload` 관련 LMS 자체 경고와 우리 beforeunload 우회 로직을 분리해 볼 수 있습니다.

## v0.6.2 플레이어 안정화 방식
이번 버전은 자동재생을 "멈추면 계속 클릭"하는 방식에서 "새 플레이어가 완전히 안정화된 뒤 클릭"하는 방식으로 변경했습니다.

### 자동재생 순서
1. `cms.catholic.ac.kr/em/<content-id>`의 현재 content-id를 읽습니다.
2. `duration >= 60`, `readyState === 4`, `currentSrc`가 있는 실제 본편 video를 기다립니다.
3. `content-id + currentSrc + duration + readyState` 조합이 1.8초 동안 변하지 않아야 새 플레이어가 완전히 만들어진 것으로 인정합니다.
4. 안정화 뒤 0.7초를 추가로 기다립니다.
5. 클릭 직전에도 동일한 video 객체, src, duration인지 다시 확인합니다.
6. 모든 조건이 유지될 때 `.vc-front-screen-play-btn`을 딱 한 번 클릭합니다.
7. `currentTime`이 1.2초 이상 실제로 증가해야 재생 성공으로 판단합니다.
8. 이후 동일한 video 객체/src/content-id가 그대로인 상태에서 0~12초 구간에 1.5초 이상 멈춘 경우에만 복구 클릭을 딱 한 번 허용합니다.
9. 플레이어가 교체되거나 src가 바뀌면 클릭하지 않고 다시 안정화 단계로 돌아갑니다.

### 제거한 방식
- 반복적인 재생 버튼 연타
- `video.click()`
- 페이지 reload
- iframe reload
- 자동재생 과정의 `location.href` 재이동

따라서 LearningX/CMS 초기화 중간 상태를 건드리지 않고, 완성된 새 플레이어만 조작하도록 설계했습니다.

## v0.6.4 preloader → 본편 2단계 재생
실제 CMS 프레임에서 확인한 결과, 강의 진입 직후에는 본편 video가 존재하지 않고 `preloader.mp4`(약 1.066초)만 로드되어 있었습니다.

기존 v0.6.2/v0.6.3은 `duration >= 60`인 본편 video가 먼저 나타나기를 기다렸기 때문에, 첫 재생 클릭 자체가 발생하지 않을 수 있었습니다.

이번 버전은 실제 로딩 순서에 맞춰 상태 머신을 변경했습니다.

1. `preloader.mp4`가 로드된 것을 확인합니다.
2. preloader 단계의 `.vc-front-screen-play-btn`을 정확히 한 번 클릭합니다.
3. 그 뒤에는 본편 video가 생길 때까지 절대 추가 클릭하지 않습니다.
4. `preloader.mp4`가 아닌 60초 이상 본편 video가 나타나면 1.2초 안정화 시간을 둡니다.
5. 본편이 이미 재생 중이면 아무것도 하지 않습니다.
6. 본편이 멈춰 있을 때만 재생 버튼을 정확히 한 번 클릭합니다.
7. 이후에는 `currentTime`이 실제로 증가하는지만 확인하고 자동재생 로직은 더 이상 플레이어를 건드리지 않습니다.

따라서 인트로/preloader를 본편으로 오인하지 않고, preloader 시작과 본편 시작을 서로 다른 단계로 처리합니다.
## v0.6.5 UniPlayer 내부 재생 이벤트 사용
CMS 콘솔에서 실제 테스트한 결과 아래 명령이 영상을 정상 재생시키는 것을 확인했습니다.

`uniPlayer._uniPlayerEventTarget.fire("vc-front-screen-play-selected")`

재생 버튼의 실제 jQuery handler도 내부적으로 `VCFrontScreenEvent.PLAY_SELECTED`를 fire하는 구조였습니다.

따라서 v0.6.5부터는:
- `.vc-front-screen-play-btn.click()`을 자동재생 수단으로 사용하지 않습니다.
- `video.play()`를 사용하지 않습니다.
- preloader와 본편을 클릭으로 따로 조작하지 않습니다.
- CMS MAIN world에 `uniplayer-main.js`를 설치하고, 실제 UniPlayer 내부 이벤트를 직접 발생시킵니다.
- isolated content script는 `chrome.storage`에서 자동재생 활성화 상태를 확인한 뒤 MAIN world bridge에 재생 요청만 보냅니다.
- MAIN world에서 `window.uniPlayer._uniPlayerEventTarget.fire("vc-front-screen-play-selected")`를 실행합니다.
- 본편 종료 감지와 다음 강의 이동 로직은 기존 구조를 유지합니다.

이 방식은 사용자가 직접 재생 버튼을 눌렀을 때 UniPlayer 내부에서 실제로 발생하는 재생 이벤트와 같은 경로를 사용합니다.
## v0.6.6 Chrome userGesture 재생 실험
실제 CMS 콘솔에서 `uniPlayer._uniPlayerEventTarget.fire("vc-front-screen-play-selected")`가 재생을 시작하는 것을 확인했지만, 확장프로그램이 같은 이벤트를 자동 호출하면 Chrome에서 `NotAllowedError: play() failed because the user didn't interact with the document first`가 발생했습니다.

이번 버전은 일반 JavaScript 클릭이나 이벤트 위조 대신 Chrome DevTools Protocol을 사용합니다.

- `debugger` 권한을 추가했습니다.
- CMS가 플레이어 준비 상태가 되면 content script가 background에 재생을 요청합니다.
- background는 CMS의 실제 기본 execution context를 찾습니다.
- `Runtime.evaluate(..., userGesture: true)`로 CMS MAIN world에서 아래 이벤트를 실행합니다.
  `uniPlayer._uniPlayerEventTarget.fire("vc-front-screen-play-selected")`
- 즉 실제 재생 버튼이 호출하는 UniPlayer 내부 경로는 그대로 유지하면서, 브라우저가 사용자 동작으로 처리할 수 있는 CDP userGesture 옵션을 사용합니다.
- 자동재생 중지 시 debugger 연결을 해제합니다.
- 종료 감지와 다음 강의 이동 로직은 기존 구조를 그대로 유지합니다.

주의: Chrome의 `debugger` 권한을 사용하기 때문에 테스트 중 브라우저 상단에 디버깅 관련 안내가 표시될 수 있습니다.
## v0.6.7 종료 감지 안정화
v0.6.6에서는 `ended` 이벤트가 발생한 순간 `video.currentTime`이 영상 끝부분인지 다시 확인했습니다.
일부 UniPlayer 상태에서는 종료 직후 `currentTime`이 재설정되거나 video 상태가 바뀌어, 실제로 강의가 끝났는데도 다음 강의 요청이 누락될 수 있었습니다.

- 종료 순간의 `currentTime` 대신 재생 중 관찰한 최대 재생 위치(`maxObservedTime`)를 기준으로 실제 끝까지 재생됐는지 확인

- `ended` 이벤트가 누락되더라도 끝부분까지 재생된 뒤 정지된 상태를 보조 감시하여 다음 강의 요청
- 자동재생/CDP userGesture 구조와 다음 강의 이동 로직은 그대로 유지
